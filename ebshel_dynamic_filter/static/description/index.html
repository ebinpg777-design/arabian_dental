1The ribbon

One ribbon, any model

If it has a list or a kanban view, it can have tiles — sitting between the control panel and the records, where everybody already looks. Each one is a label, a live number, a trend, and a filter behind it.

Two named rows on Contacts: clean two-line tiles, each marked by a bar of its own colour, the trend drawn behind the number — with goal rings, a private tile (dashed inner line) and one tile past its threshold.

Four styles, one click apart

Flat and clean, no gradients. Accent — a white card with a bar of colour down its left edge — is the default; Card, Midnight and Pastel are one click away under “Tile style” in the tile menu. Each user picks their own, kept per model.

Tiles that tell you when they move

When a number changes at the next refresh — auto-refresh, or a colleague’s edit — the tile flashes and shows by how much, “+2” or “−1”, for a few seconds. Filtering the view does not count: only a move under the same filter is news. Here two contacts were added, and “People” and “Added this month” say so.

2Filtering

A tile is a filter, not a picture

Click one and it becomes an ordinary, removable search facet — every other filter keeps working, and the neighbouring tiles recount themselves against what is left. Select several and choose whether records must match any of them or all.

The Multi-select checkbox beside “Add a row” is on: every click adds to the selection, and “match any” keeps the records that match either tile — “Companies or With an email”. Ctrl-click does the same without the mode.

3Breakdown

Break a tile open

A tile answers how many. One click answers of what — split by status, salesperson, country or month, in a single grouped read.

  • Picks its own field — status, stage, responsible — unless you chose one.
  • Follows the measure: a revenue tile breaks down into revenue.
  • Click a row and the view narrows to tile + slice, as one removable facet.
  • One query, not one per row.
4Layout

Stack the rows, size the tiles

One row is rarely enough. Add up to six, name them in the pane down their left, drag tiles between them, and give each row its own height. Drag a tile's edge and it keeps that width for everybody.

A tile is a compact two-line card: the sparkline sits behind the number. A tall row turns it back into a chart; a short one drops the sub-label, then steps the number down a size — nothing is ever clipped.

5Thresholds

Tiles that watch themselves

Give a tile a limit and it stops being decorative: it turns into a warning the moment the number crosses the line, and — if you ask it to — tells you even when nobody has the view open.

  • On screen — the tile takes the warning colour and breathes slowly.
  • Off screen — an hourly check pushes a notification with a “Show me” button that opens the records.
  • No spam — only the crossing notifies, never the state.
  • The right people — the owner, the restricted groups, or the managers.
6The Tile Wall

Every ribbon in the database, on one screen

Tiles live above a view, which makes them invisible until you go looking. The Wall turns them into a morning overview — grouped by model, alerting tiles first — and each one still opens its records, filtered. “Live” refreshes it every minute.

7The smart search panel NEW

Odoo’s side panel, made to be used

The column of categories and filters on the left of Employees, Products, Documents and every other view that has one gets the tools it was missing — in every app, with no configuration. It is slimmer, too: 188 px instead of 220, with the find box and its tools on a single line, and the spacing trimmed to what reading needs — more room for your records. “Classic look” in the panel menu gives Odoo’s own panel back.

Employees: the current selection as removable chips at the top, a count and a clear button on each section, and every value's share of its section drawn behind it. The tiles above were made from the Department section in one click. (The Tags section is added to this demo's search view; Department is Odoo's own.)

Find in panel — one box for every section, ignoring case and accents. The match is highlighted and the tree opens down to it.

Saved selections — name the combination you keep rebuilding (“R&D talent”) and get it back in one click.

Your panel, your way — most records first or alphabetical, hide empty values, compact rows, collapse every section. Kept per model.

Straight to tiles — turn a section into a tile set, the busiest values ticked, each tile filtering exactly as the panel does — or pin a single value with the thumbtack.

  • Star a value and it stays at the top of its section, whatever the sort — the handful you use every day, first.
  • Select all, or invert a checkbox section in one click, from its header.
  • Type, then Enter: the first match in the find box is applied, as if you had clicked it.
  • Group the view by a section’s field, straight from its header.

Compact or comfortable, collapsed or open, auto-refresh off or every 30 seconds — kept per model, in your browser, without touching what colleagues see.

Keyboard first

Alt+1…9 applies a tile, Alt+0 clears them. The number shows on hover, so it teaches itself.

Tiles are records

Searchable, groupable, multi-editable, archivable, translatable and exportable like anything else in Odoo — one list manages them all.

12Permissions

Private tiles, shared tiles

Dashboard modules usually force a choice between “everybody sees it” and “nobody may build one”. Here both exist — and it is the record rules, not the interface, that keep them apart.

Any internal user Filter Tiles / Manager
Use the tiles, break them down, set density and row heights Yes Yes
Build tiles only they can see Yes Yes
Take a private copy of a shared tile Yes Yes
Publish a tile to everybody No Yes
Edit, resize, reorder, generate and delete the shared ribbon No Yes
Shared tiles can be restricted to user groups, to a company, to list or kanban views, and to a single menu. Nobody's private tile is visible to anybody else — it does not even appear in the administrator's list.
13Under the hood

Fast by design, safe by default

One RPC for definitions

Cached once per session. Opening a list view of a model without tiles costs exactly zero extra round-trips.

One RPC for values

Ten tiles are one batched call, debounced against the search bar — and a stale answer can never overwrite a fresh one.

Never blocks a view

Values load beside the records, never in front of them. If the service fails, the view still opens — the ribbon simply is not there.

Your rights, always

Every number is counted as you, without sudo. A tile can never surface a record you are not allowed to open.

No core data touched

Three small models, one technical group, two scheduled actions. No modified views, no patched records — uninstall and every trace goes with it.

Tested

An automated suite ships with the module, covering values, thresholds, history, breakdowns, layout, import/export and the whole permission matrix.

15FAQ

Questions people actually ask

Do I need a developer to add a tile?

No. Filter the list the way you normally would, click the “+” tile, give it a name and a colour. Everything else — icon, measure, trend, threshold, width — is optional.

Does it work on Community, Enterprise and Odoo.sh?

All three, from the same package. It depends only on web and bus, which every Odoo installation has, and imports nothing Enterprise-only. On Odoo.sh it is an ordinary addon — push it to your branch.

Will it slow my lists down?

Tile definitions are cached per session, and a whole ribbon of values is one batched call that runs beside the records rather than before them. A model with no tiles costs nothing.

Can a tile leak data to the wrong person?

No. Every number is counted with the reader's own access rights and record rules. The two background jobs — recorded history and the threshold check — run as the tile's owner for a private tile, and server-side for a shared one, because a stored daily number has to be the same number for everybody.

What happens to my tiles when I upgrade?

They are ordinary records in your database, not code. Upgrading keeps them, and you can export a ribbon to JSON to carry it into another database.

Does it work on models added by other apps, or by Studio?

Yes. Tiles are attached to a model, not to a view file, so anything with a list or kanban view qualifies — including models you created yourself.

Can users mess up the shared ribbon?

Only Filter Tiles managers publish, edit, reorder or delete shared tiles. Everybody else builds private tiles and takes private copies — usually exactly what they wanted.

What if I uninstall it?

Everything the module added goes with it: the models, the group, the scheduled actions and the tiles themselves. No core view or record was modified, so nothing is left behind.
